## Setting up Supabase

### 1. Go to the [Supabase website](https://supabase.com/) and create an account.

### 2. Create a new project (don't adjust any of the default settings).

### 3. Store the archive files in Supabase.

Go to *Storage -> Files -> Buckets* and select *New bucket*. Name this bucket "Archive Files" and turn on *Public bucket*. After that, create three new folders within the bucket titled "txt", "pdf", and "docx". From here, just drag and drop the appropriate file types from the *archives* folder in this repository into the Supabase folders.

### 4. Create a new policy to allow access to the bucket you created.

Go to *Storage -> Files -> Policies* and select *New policy* next to the *Archive Files* bucket. Click *For full customization*. Fill out the sections accordingly:
- Policy name: Public can list Archive Files
- Allowed operation: SELECT only
- Target roles: leave blank for all roles
- Policy definition (USING): bucket_id = 'Archive Files'

Finally, hit *Review* and then *Save*.

### 5. Create the database.

Go to the *SQL Editor* tab and paste the following SQL code then hit *Run* in the upper right corner.

```bash
/*
Create the tables
*/

create table public."user" (
  email character varying not null,
  name character varying not null,
  is_admin boolean not null default false,
  user_id uuid not null default auth.uid (),
  phone_number character varying null,
  constraint users_pkey primary key (user_id),
  constraint users_email_key unique (email),
  constraint users_user_id_fkey foreign KEY (user_id) references auth.users (id)
) TABLESPACE pg_default;

create table public.thread (
  name character varying not null,
  description text not null,
  constraint thread_pkey primary key (name)
) TABLESPACE pg_default;

create table public.post (
  post_id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  subject character varying not null,
  text text not null,
  thread_name character varying not null,
  user_id uuid not null default gen_random_uuid (),
  is_edited boolean not null default false,
  edit_time timestamp with time zone null,
  constraint post_pkey primary key (post_id),
  constraint post_thread_name_fkey foreign KEY (thread_name) references thread (name),
  constraint post_user_id_fkey foreign KEY (user_id) references "user" (user_id)
) TABLESPACE pg_default;

--Turn on RLS
alter table public.users enable row level security;
alter table public.thread enable row level security;
alter table public.post enable row level security;

--Make public.users readable without triggering the users policies
create or replace function public.is_admin()
returns boolean language sql stable security definer set search_path = public as 
$$select coalesce((select is_admin from public.users where user_id = auth.uid()), false);$$;

--Add thread policies
create policy "threads readable by signed-in users" 
    on public.thread for select
    to authenticated
    using (true);
create policy "profiles readable by signed-in users"
    on public.users for select
    to authenticated
    using (true);
create policy "users create own profile"
    on public.users for insert
    to authenticated
    with check (user_id = auth.uid() and is_admin = false);

--Add post policies
create policy "posts readable by signed-in users"
    on public.post for select
    to authenticated
    using (true);
create policy "users create own posts"
    on public.post for insert
    to authenticated
    with check (user_id = auth.uid());
create policy "users edit own posts"
    on public.post for update
    to authenticated
    using (user_id = auth.uid())
    with check (user_id = auth.uid());
create policy "users delete own posts, admins delete any"
    on public.post for delete
    to authenticated
    using (user_id = auth.uid() or public.is_admin());
```

### 6. Update the website for your specific Supabase project.

Go to the *forum.js* and *archives.js* files found in the *js* folder of this repository and edit the values for *SUPABASE_URL* and *SUPABASE_ANON_KEY*. These values can be found in *Project Overview* -> *Server Build APIs* from inside your Supabase project (note that SUPABASE_ANON_KEY is called SUPABASE_PUBLISHABLE_KEY within Supabase).

### 7. Update the email confirmation link.

After the website has been published, go to *Authentication -> URL Configuration* in Supabase and change the *Site URL* to the URL for the forum page.

### You're all set!



## How to create a new forum thread

### 1. Go to the *Table Editor* tab in your Supabase project.

### 2. Click the *thread* table.

### 3. Select *Insert* -> *Insert Row* in the upper right corner.

### 4. Fill in the *name* and *description* boxes with your desired values.

### 5. Hit *Save*!



## How to make a user an admin

### 1. Go to the *Table Editor* tab in your Supabase project.

### 2. Click the *user* table.

### 3. Right click anywhere on the row representing the user you want to make an admin and click *Edit row*.

### 4. Change the *is_admin* value to *TRUE* and hit *Save*!



## How to ban a user

### 1. Go to the *Authentication* tab in your Supabase project.

### 2. Click the *Users* tab under *MANAGE*.

### 3. Click the UID of the user you would like to ban.

### 4. Scroll down on the side menu that pops up and select *Ban user*.

### 5. Set the ban duration bfore simply hitting *Confirm ban*!



## Setting up the contact form

The Contact page sends messages to email using **Web3Forms** (web3forms.com), a free service. There is no server or database to manage. Below is what you may need to change.

### 1. Current setup
- **Messages currently go to:** `nfastandin@gmail.com` (a temporary stand-in account the student team created)
- **Web3Forms account login:** `nfastandin@gmail.com` (Web3Forms logs in by email link, so whoever controls this Gmail controls the form)
- **Access key location:** `js/contact.js`, line 13

### 2. How to change the email that receives messages
**Recommended way (about 5 minutes):**
1. Go to **web3forms.com** and create a new access key using the email that should receive messages (for example, `nfatournamentcommittee@gmail.com`).
2. Open that inbox and copy the access key from the Web3Forms email (check Spam).
3. Open `js/contact.js` and replace the key on **line 13**. Keep the quotes:
       tournament: 'NEW-KEY-GOES-HERE',
4. Save, commit, and push to GitHub.
5. Send a test message from the Contact page to confirm it arrives.

The old stand-in key can simply be ignored or deleted from the stand-in's Web3Forms dashboard afterward.

**Optional: separate inbox for the Journal (NFJ).** Create a second key with `nfajournal@gmail.com` and put it on **line 14** of `js/contact.js` in place of `PASTE_JOURNAL_KEY_HERE`. NFJ messages will then go to the journal inbox; everything else goes to the line 13 inbox. If line 14 is left as-is, all messages go to the line 13 inbox.

### 3. Backup "email us" links
If the form ever fails, visitors are shown an "Open in Email Client" button. These addresses are set separately from the key:
- `js/contact.js` line 37 (fills in the backup button after a failed send)
- `html/contact.html` lines 133 and 143
- `html/contact.html` lines 216 and 223 (the "Key Committee Contacts" list)

Update these if the official NFA emails ever change.

### 4. Limits and cost
- **Free plan: 250 messages per month.** This resets monthly.
- **It will NOT charge you.** No credit card is ever entered on the free plan. If more than 250 messages come in during one month, the form simply stops sending until the next month, and visitors will see an error telling them to use the "Open in Email Client" button instead.
- Upgrading is optional. Paid plans allow thousands of messages per month; see web3forms.com/pricing for current prices.
- Web3Forms only keeps its own copy of messages for 30 days. The emails themselves stay in Gmail permanently.

### 5. When the site goes live
When the website is published at its real web address:
- Log in to the Web3Forms dashboard and update the form's **Website URL** from `localhost` to the real address.
- The first few messages may land in Spam. Mark them "Not spam" so future ones arrive in the inbox.

### 6. Do not remove
- The access key in `js/contact.js` is **not a password**. Web3Forms keys are designed to be public, so it is safe on GitHub.
- `html/contact.html` line 6 must keep `connect-src 'self' https://api.web3forms.com;`. Without it, the browser blocks the form from sending.
